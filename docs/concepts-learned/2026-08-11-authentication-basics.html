Today's Concept: How Sign-In Actually Works in This App

Tuesday, August 11, 2026

The one-sentence version

This app does not have its own login system. It sends you to Microsoft to prove who you are, and Microsoft hands back a signed "receipt" (a token) that this app trusts.

The hotel key-card analogy

Think of Microsoft Entra ID as a hotel front desk, and this app as one of the hotel's rooms.
  • You never get a room key directly from the room — you go to the front desk first.
  • The front desk checks your ID (and, if MFA is turned on, also texts you a code to confirm it's really you).
  • Once satisfied, the front desk hands you a key-card that's programmed to open exactly your room, for a limited time.
  • The room door doesn't know your name or password — it only checks "is this a valid key-card?" That's exactly what this app's MsalInterceptor does with every API request.

The key terms, explained simply

  • Microsoft Entra ID — Microsoft's identity service (used to be called "Azure AD"). It's the front desk in the analogy above. It's a completely separate system from this app.
  • MSAL (Microsoft Authentication Library) — the toolkit this app uses to talk to Entra ID. It's the "phone line" between the app and the front desk.
  • Token — the key-card. A signed piece of data proving "this person signed in successfully, and is allowed to access this specific API, until this expiry time."
  • Client ID — this app's own ID number, so Microsoft knows which app is asking.
  • Tenant ID — which organization's Microsoft directory to check against (like which hotel chain, not just which hotel).
  • Scope — the specific permission being requested (e.g. "access to ROIVIO's backend API"), like requesting a key-card that only opens your room, not the whole hotel.
  • Redirect flow — instead of a pop-up window, the whole browser tab briefly navigates to Microsoft's sign-in page, then comes back. This app deliberately uses this instead of a pop-up because Vercel's security settings block pop-ups from reporting back successfully.
  • Guard (MsalGuard) — a checkpoint on certain pages (like the dashboard) that says "don't let anyone in here without a valid key-card first."
  • Interceptor (MsalInterceptor) — automatically staples the key-card (token) onto every outgoing request to this app's own backend, so no individual feature has to remember to do it.

Where MFA fits into this picture

Multi-factor authentication (MFA) — being asked for a second proof, like a phone code, in addition to your password — happens entirely on Microsoft's side, during the "front desk" step. This app never sees or handles that second factor directly; it only finds out afterward whether sign-in succeeded.

That's why turning MFA "on" for this app is mostly a decision made in the Microsoft Entra admin center, not a code change in this repository — unless we decide we need our own additional check on top of Microsoft's.
